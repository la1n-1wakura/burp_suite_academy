# 1.Резюме

Пхоже на предыдущую лабораторную, отличие лишь в том, что не смотря на 2 столбца доступных для `UNION` объединения, пользоваться можно только вторым, посколько только он может конвертироваться в текст.

В ходе тестирования веб-приложения `https://lab-target.web-security-academy.net` была обнаружена **SQL-инъекция (SQLi)** в фильтре категорий товаров.

**Тип уязвимости**: Некорректная конкатенация пользовательского ввода в SQL-запрос.

**Воздействие**: Злоумышленник может модифицировать логику запроса и получить данные, которые не должны отображаться(включая логин и пароль администратора).

**Результат**: По условию задания с помощью `UNION SELECT` нужно получить пароль администратора и войти под соответствующей УЗ.

# 2.Поиск и эксплуатация уязвимости
Сразу применяем филтр и по выводу видем, что, скорее всего, в основном запросе два столбца. Попытаемся проверить наличие узвимости и сразу узнаем версию БД. После нескольких попыток, оказалось, что второй столбец модет возвращать текст
Запрос: `https://lab-target.web-security-academy.net/filter?category=Accessories' UNION SELECT NULL, version() --`
*Рисунок 1 - Результат sqli*
![sqli_res](images/sqli_res.png)

По условию мы знаем, что в таблице `users` есть столбцы `username` и `password`. Только теперь нам придёт поочереди вытягивать значения каждого столбца из соответствующего запроса. 
Пример с `username`: `https://lab-target.web-security-academy.net/filter?category=Accessories' UNION SELECT NULL, username FROM users --`
